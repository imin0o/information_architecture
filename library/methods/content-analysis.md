# コンテンツ分析とコンテンツ一覧

情報環境に実際にあるコンテンツを調べ、一覧にして、分類や構造の材料にする方法である。ia-analysisでコンテンツ一覧を作るときに使う。

## 手順

1. 実際にあるコンテンツを詳しく見て、戦略側の想定と、実際のコンテンツの量や質の差を見つける [CLAIM-0039]。
2. 初期には範囲と性質を知るための大まかな調査を行い、後でページ単位のインベントリと監査を行う [CLAIM-0040]。
3. 各コンテンツについて、構造のメタデータ（見出しや区分）、記述のメタデータ（主題、対象者、形式など）、管理のメタデータ（作成者、所有者、作成日、削除時期）を記録する [CLAIM-0041]。
4. 多くのコンテンツに現れるまとまり、階層関係、関連関係のパターンを探し、分類や構造の候補にする [CLAIM-0042]。

## 適用条件

- 既存のコンテンツがある情報環境に使う [CLAIM-0039]。
- 手順2の段階分けは、調査から設計までの工程でコンテンツを扱う場合に使う [CLAIM-0040]。

## 代表ケースとの対応

ルーブリックR-04の「コンテンツ一覧の全項目が、配置済み、未処理、対象外のいずれかに区分され、未処理と対象外に理由がある」に対応する。CASE-WEBIA-001の14ページについて、手順3の記述のメタデータ（サービス種別、地区、対象者）を記録し、ファセット分類（KN-006）の材料にする。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。

- 配置済み、未処理、対象外の区分は、文献の監査（手順2）を課題ケースの合格条件に合わせて具体化したものである。対象外の理由を書く要件は文献にはなく、ルーブリックから来る。
