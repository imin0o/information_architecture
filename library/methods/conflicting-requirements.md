# 組織化の原則の明文化と要件の対立の扱い

入力資料や関係者の要件が対立するときに、対立を記録し、どの方法で解決したかを判断記録に残す方法である。ia-orchestratorとia-taxonomyで、入力資料どうしの矛盾を扱うときに使う。

## 手順

1. 複数の人が長期にわたって同じ分類や配置の原則を使う組織では、原則を規則や方針として明文化し、異なる人が一貫して適用できるようにする [CLAIM-0059]。
2. 個人や小規模な仕組みの原則は、非公式で、一貫しなかったり互いに矛盾したりすることが多い [CLAIM-0060]。入力資料にそうした原則が含まれる場合は、この可能性を前提に読む。
3. 組織化の仕組みに要件の異なる2者以上が関わると、組織化の方法について対立が生じうる [CLAIM-0061]。
4. 少人数なら、交渉で全員の要件を満たす案に合意できることが多い。関わる人が増えると対立の可能性が高まり、すべての組み合わせで個別に交渉するのは現実的でなくなる [CLAIM-0062]。
5. 多くの領域では、標準を作るか標準に従うことで対立を避ける。大規模な仕組みの対立は、法的権限や経済力を持つ当事者が上から解決策を課すことで解決されることが多い [CLAIM-0063]。

## 代表ケースとの対応

CASE-TAXONOMY-001のルーブリックR-06（入力資料どうしの矛盾を記録して判断する）に対応する。入力資料の間で分類の原則や用語が食い違う場合は、下の「仮説・補完」の記録方法に従って判断記録に書く。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。

- 入力資料の矛盾は、資料の作成者を当事者とみなして手順3〜5を適用できる。この対応づけは文献の主張ではない。
- 対立があれば、当事者（資料）ごとの要件を分けて判断記録に書き、手順4・5のどの方法で解決したか、または未解決として残したかを記録する。
- 手順1の明文化は、複数の担当者や長期の運用を前提とする仕組みに求め、1人が短期間だけ使う仕組みには求めない。
- 手順5の上からの解決は、決定する権限を持つ当事者がいる場合に限る。権限者がいない、または入力資料から特定できない場合は、対立を未解決の論点として残す。
- 文献の適用条件と案件の条件が異なる場合の扱い（NEED-09の後半）は、BOOK-005の読んだ範囲では扱われていない。判断記録の契約（M2）で、適用条件の違いを `assumptions` と `alternatives` に記録する手順で補う。
