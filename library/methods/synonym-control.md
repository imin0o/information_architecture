# 同義語と表記揺れの統合

同じ概念を指す複数の語を1つの概念にまとめ、優先ラベルを1つ決めて、残りを非優先ラベル（課題ケースの「同義語」、データ項目は alt_labels）にする方法である。ia-taxonomyで統制語彙を作るときに使う。

## 手順

1. 概念ごとに優先ラベルを1つ選び、同じ概念を指すほかの語を非優先ラベルにする。優先ラベルには利用者の言葉を反映させる [CLAIM-0011]。
2. 優先ラベルを複数の候補から選ぶときは、想定利用者が最も引きそうな語を、一般にほかの基準（組織の用語、業界の標準、コンテンツ内の表記など）より優先する [CLAIM-0013]。
3. 非優先ラベルは、検索する人を優先ラベルへ導き、語の付与を支える入口として登録する [CLAIM-0006]。書式の一貫性は求めず、利用者が入力しうる表記を幅広く入れる [CLAIM-0010]。
4. 1つの優先ラベルに複数の非優先ラベルを対応させてよい。非優先ラベルは通常1つの優先ラベルだけを指す [CLAIM-0008]。
5. 完全な同義語でなくても、対象コンテンツについて区別すると重複や混乱を招くほど近い語は、同じ概念にまとめてよい [CLAIM-0007]。
6. 近い語をまとめるかは、対象コンテンツの範囲で、優先ラベルをいつでもその語の意味で使えるかで判断する [CLAIM-0009]。

## 適用条件

- 手順3は、1画面で一覧できない規模の語彙で特に必要になる [CLAIM-0006]。
- 手順4の例外として、事前結合語を分解して2つの優先ラベルの組合せを指す一対多の参照を認める体系がある [CLAIM-0008]。
- 手順6の判断は、範囲によって同義とみなせるかが変わる語に適用する [CLAIM-0009]。

## 代表ケースとの対応

CASE-TAXONOMY-001のTASK-02では、「ハウスキーピング」「家事支援」から家事代行の情報に到達する必要がある。手順1〜4により、T-01〜T-03を同じ概念IDの優先ラベルと非優先ラベルにする。優先ラベルは、ページを作る担当者と検索する利用者のうち、利用者の語を優先して選ぶ（手順2）。CASE-WEBIA-001でも、サービス名の表記揺れに同じ手順を使う。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。採用する場合は案件の仮定として判断記録に残す。

- 日本語では、ひらがな、カタカナ、漢字、送り仮名の違いによる表記揺れが多い。これらは手順3の「利用者が入力しうる表記」として非優先ラベルに含めることが考えられる。
- 利用者が最も引きそうな語（手順2）は、検索ログや利用者調査がない場合は推定にとどまる。この場合は未検証の仮定として扱い、検証計画に検索語の確認を加える。
