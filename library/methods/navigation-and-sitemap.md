# 組織化の構造、ナビゲーション、サイトマップ

分類した内容を、利用者が移動できる構造とナビゲーションにまとめ、サイトマップとして示す方法である。ia-structureでサイトマップと探索経路を設計するときに使う。

## 手順

1. 組織化の方式（コンテンツの共通の特徴によるまとめ方）と、組織化の構造（項目やグループの関係の種類）を分けて考える。どちらも見つけやすさと分かりやすさに影響する [CLAIM-0028]。
2. 全体の構造は、階層、データベース型、ハイパーテキストを補い合う形で組み合わせる。構造が利用者の主な移動方法を決める [CLAIM-0033]。
3. 階層の幅（各階層の選択肢の数）と深さ（階層の数）を釣り合わせる [CLAIM-0032]。
4. ページに組み込むグローバル、ローカル、文脈のナビゲーションで、利用者が今どこにいて、どこへ行けるかを分かるようにする [CLAIM-0050]。
5. 必要に応じて、サイトマップ、索引、ガイドなどの補助ナビゲーションで、同じ情報への別の経路を用意する [CLAIM-0051]。
6. サイトマップなどの図では、コンテンツの構成単位（何を単位とし、どうまとめ、どう並べるか）と、構成単位どうしのつながりを示す [CLAIM-0049]。

## 適用条件

- 手順3は、階層型のナビゲーションを設計する場合に使う。狭く深すぎると選択を重ねる回数が増え、広く浅すぎると最初の選択肢が多くなる [CLAIM-0032]。
- サイトマップとワイヤーフレームは構造を表すことに重点があり、コンテンツやラベルの意味は伝えにくい。意味は統制語彙や判断記録で補う [CLAIM-0048]。

## 代表ケースとの対応

ルーブリックR-05の「各主要タスクについて、ルートから到達先までの経路がノードIDで示される」に対応する。CASE-WEBIA-001のTASK-02（見守りの料金と申込み方法）は、P-05からP-08とP-10へ移動できる必要があり、手順4の文脈のナビゲーションで結ぶ。TASK-04（問い合わせ窓口）は、手順5の補助ナビゲーションか、グローバルナビゲーションから到達させる。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。

- 14ページ程度の小さなサイトでは、深さを2階層までに抑えても幅が過大になりにくいと考えられる。実際の判断は利用者による検証（KN-010）で確かめる。
