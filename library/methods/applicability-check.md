# 文献の適用条件と案件の条件の照合

文献や一般的な手法を根拠に判断するとき、その適用条件が案件の条件に合うかを照らし合わせ、合わない場合の扱いを判断記録に残す方法である。ia-orchestratorと各段階のSkillで、知識を判断の根拠に使うときに使う。

## 文献の主張

1. 情報設計の状況はそれぞれ固有である。業界のベストプラクティスや他社の模倣が広がっても、個々の情報システムは独自のものになる。利用者・コンテンツ・文脈のモデルは、個別の案件に固有の要求と機会を知るための道具である [CLAIM-0064]。
2. 一般的な答えが決まらない問いには「場合による」と答えたうえで、問いを利用者・コンテンツ・文脈の3つに分けて答えを組み立てる [CLAIM-0065]。
3. 設計では、事業の目的と使える資源（文脈）、コンテンツの性質と量と変化、利用者の要求と情報探索行動の3つを理解する必要がある [CLAIM-0026]。
4. 3つの変数の組合せは情報環境ごとに異なり、同じ環境でも時間とともに変わる [CLAIM-0027]。

## 代表ケースとの対応

CASE-TAXONOMY-001のルーブリックR-06（文献の適用条件と案件の条件の違いを記録して判断する）に対応する。照合の手順は下の「仮説・補完」による。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。上の主張から立てた運用の手順である。

- 一般的な手法やベストプラクティス、他の事例を、照合せずにそのまま案件の答えとして使わない（主張1から）。
- 知識本文の「適用条件」が前提にしている利用者・コンテンツ・文脈を、案件の入力から確かめた3つと比べる（主張2〜4から）。
- 比べた結果を、合う・合わない・入力から分からない、のどれかとして判断記録に書く。
- 適用条件が合わない知識は、その判断の根拠に使わない。合うかどうか入力から分からない場合は、合うと仮定した内容を `assumptions` に書き、その仮定が外れた場合の案を `alternatives` に書く（判断記録の契約、M2）。
- 文献どうしの推奨が食い違う場合は、それぞれの適用条件を `library/conflicts.yaml` の記録と照らし、案件の条件に合う方を採る。どちらも合わなければ未解決として残す。
