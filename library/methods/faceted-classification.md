# ファセット分類

独立した複数の属性（ファセット）でコンテンツを記述し、属性を組み合わせて絞り込めるようにする方法である。ia-taxonomyで分類体系を、ia-structureで複数の入口を持つ探索経路を設計するときに使う。

## 手順

1. 対象コンテンツの性質からファセットを決める。汎用のファセット例をそのまま使わない [CLAIM-0023]。
2. コンテンツに共通するパターンから検索の観点を先に決め、その後で各ファセットに語を入れる [CLAIM-0025]。
3. 各ファセットは独立した階層とし、互いに排他的にする。各ファセットから1語ずつ組み合わせて検索できるようにする [CLAIM-0022]。
4. 同じコンテンツを主題別と形式別のように別の方式で並べる場合、同じ項目が両方の一覧に現れるのは当然であり、これを重複として扱わない [CLAIM-0031]。
5. 意味の重なる2つの語を両方残す場合は、別のファセットに置く [CLAIM-0014]。

## 適用条件

- ファセット分類は、共通の特徴を持つレコードで構成されたコンテンツに最も向く [CLAIM-0023]。種類の近いコンテンツの集まりほど、多くのファセットを置ける [CLAIM-0024]。
- すべてのファセットがすべてのコンテンツに当てはまる必要はなく、多くのコンテンツが多くのファセットで記述できればよい [CLAIM-0024]。
- 名前で探す利用者には、アルファベット順のような正確な方式が使いやすい。名前を知らない利用者には役立たないため、主題などの別の方式と組み合わせる [CLAIM-0029]。

## 代表ケースとの対応

CASE-WEBIA-001の必須条件「地区とサービス種別のどちらから探し始めても、serviceページ（P-02〜P-07）へ到達できる」と、ルーブリックR-05の「複数の属性で絞り込むタスクでは、どの属性から入っても到達できる」に対応する。地区とサービス種別を別のファセットにし（手順3）、TASK-03（自分の地区で利用できるサービスの一覧）を地区ファセットの選択で実現する。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。

- serviceページは種類のそろったコンテンツであり、適用条件の「共通の特徴を持つレコード」に当たると考えられる。一方、お知らせや問い合わせ窓口のページは同じファセットで記述しにくいため、ファセットの対象外として別の経路に置く案が考えられる。
