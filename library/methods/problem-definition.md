# 利用者、コンテンツ、文脈による問題定義

設計を始める前に、利用者、コンテンツ、文脈（事業の目的と資源）の3つを整理し、後の構造や分類の判断と結び付ける方法である。ia-analysisで問題定義を作るときに使う。

## 手順

1. 文脈として、事業の目的と、設計や実装に使える資源を整理する [CLAIM-0026]。
2. コンテンツとして、現在のコンテンツの性質と量、今後の変化の見込みを整理する [CLAIM-0026]。
3. 利用者として、主な利用者の要求と情報探索行動を整理する [CLAIM-0026]。
4. 3つの領域はどれも設計に影響し、いずれも変化することを前提にする。変数の組合せは情報環境ごとに異なり、同じ環境でも時間とともに変わる [CLAIM-0027]。

## 適用条件

- ウェブサイト、イントラネット、アプリなどの情報環境の設計を始める場合に使う [CLAIM-0026]。
- 手順4により、問題定義の各項目は一度決めて終わりにせず、前提として記録し、変化したときに見直す [CLAIM-0027]。

## 代表ケースとの対応

ルーブリックR-01の「問題定義に、設計対象、利用者、目的、利用環境が書かれ、それぞれ入力の位置か仮定に対応している」に対応する。CASE-WEBIA-001では利用環境が資料にないため、手順1〜3のうち欠けた項目を不足として質問し、回答がなければ仮定として記録する（IN-03、IN-04）。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。

- 課題ケースの「利用環境」は、文献の文脈（事業の目的と資源）と利用者の情報探索行動の両方にまたがる。問題定義では、利用環境を独立した項目として書き、どちらの領域の情報かを示すと追跡しやすいと考えられる。
