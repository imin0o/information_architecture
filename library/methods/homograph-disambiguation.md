# 同名異義語の区別

同じラベルで意味の異なる概念を、語を付ける担当者と、検索・閲覧する利用者の両方が選び分けられるようにする方法である。統制語彙とタクソノミーの作成（ia-taxonomy）で使う。

この本文の主張はすべて未レビューであり、人による原典照合と主張レビューが終わるまで仮説として扱う。採用状態は`iakit library check`の出力で確かめる。

## 手順

1. 同じ綴りで意味の異なる語を見つけたら、意味ごとに別の概念に分け、ラベルに括弧の限定語を付けて区別する [CLAIM-0001]。
2. 限定語は、分野で表す形式（例：天文学、神話）か、種類で表す形式（例：惑星、神）のどちらかに決め、タクソノミー全体でそろえる [CLAIM-0002]。
3. 一方の語形だけで意味が定まる場合は、その語に限定語を付けなくてよい [CLAIM-0003]。
4. スコープノート（scope note）で区別を補う。スコープノートは、語の適用範囲を狭めたり広げたりする、意味の重なる語を区別する、使い方を助言する、のいずれかに使う。意味の重なる2語には、互いを参照する注記を付けてよい [CLAIM-0004]。
5. 区別をスコープノートだけに任せない。利用者は注記を読まないか、注記があることを知らない場合がある [CLAIM-0005]。

## 適用条件

- 括弧の限定語は、用語を管理する仕組みと表示先が括弧を含むラベルを扱える場合に使う [CLAIM-0001]。
- スコープノートは、自明な意味を説明する辞書的な定義には使わない [CLAIM-0004]。
- 手順5は、利用者が検索結果や一覧でラベルだけを見て語を選ぶ場合に特に必要になる [CLAIM-0005]。

## 例外

- 表示先が括弧を扱えない場合の代わりの方法は、登録済みの根拠にない。下の「仮説・補完」を参照する。

## 代表ケースとの対応

CASE-TAXONOMY-001のTASK-03では、候補語T-11とT-12が同じ「サポート」で、サービスの総称と問い合わせ窓口という別の意味を持つ。ルーブリックR-02は、別の概念IDに分けてscope_noteで区別することを求める。手順1・2・5を適用すると、scope_noteに加えて優先ラベル自体も限定語で区別する案になる。この適用は案件側の判断であり、判断記録には文献の適用条件（表示先が括弧を扱えるか）と案件の条件の対応を書く。

## 仮説・補完

次の内容は登録済みの文献主張に基づかない。採用する場合は案件の仮定として判断記録に残す。

- 日本語には単数形と複数形の区別がほとんどないため、語形の違いで同名異義語を区別できる場面は英語より少ないと考えられる。
- 表示先が括弧を扱えない場合は、ラベルの語自体を言い換える（例：「サポート」を「サービス案内」と「問い合わせ窓口」に分ける）方法が考えられる。この方法は利用者の語から離れる可能性があり、検索語の同義語として元の語を残すかを検証する必要がある。
